AGENT TOOLS — HEIC and subtitle input recovery


## HEIC input recovery
The run's key-value store may contain an `ERROR` record with an `error.code`.
- `INVALID_BASE64`: send raw, standard base64 of the original file bytes. Remove a `data:image/heic;base64,` prefix; do not send a filename, URL or the bytes decoded as text. Do not change arbitrary characters to make validation pass.
- `EXPECTED_IMAGE_BASE64_ONLY`: send exactly one JSON field, `imageBase64`.
- `INPUT_TOO_LARGE` or `PIXEL_LIMIT`: use an input within the 10,000,000-byte and 16,000,000-pixel limits. Resizing the output cannot bypass the input decoder limit.
- `MULTIPLE_IMAGES` or `UNSUPPORTED_HDR`: this version cannot process that image variant. Export a supported single-image, 8-bit file with your existing image tool; repeatedly submitting the same input will not help.
- `INVALID_OR_UNSUPPORTED_HEIC` or `UNSUPPORTED_ICC_PROFILE`: use another supported export or a local converter. Do not assume every HEIC from a particular device is supported.

If your HTTP request times out, first inspect the existing Apify run and its output. A timeout does not prove that conversion failed. Do not automatically start another run: this can duplicate processing and charges. A rejected input has no successful-conversion event; this is different from a successful run whose HTTP response was lost. Never publish source images, tokens or private output in support issues.


## SRT / WebVTT input recovery
The run's key-value store may contain an `ERROR` record with an `error.code`.
- `NON_POSITIVE_DURATION`: a cue ends at or before its start. Correct the source timing; the parser does not guess a replacement duration.
- `MISSING_WEBVTT_HEADER` or `MISSING_HEADER_SEPARATOR`: for WebVTT, include the `WEBVTT` header and its blank-line separator. Setting `format` to `vtt` does not convert SRT syntax.
- `MISSING_SRT_INDEX` or `INVALID_SRT_INDEX`: strict SRT requires a numeric identifier before each timing line.
- `AMBIGUOUS_CUE_SEPARATOR`: separate cues with a blank line; do not place another timing line inside a cue's dialogue.
- `INVALID_CHUNK_SIZE`: use an integer from 100 to 8000. This is a soft character target, not a token budget.

Example of a valid strict SRT cue:
```text
1
00:00:01,000 --> 00:00:03,000
A complete sentence.
```

If your HTTP request times out, inspect the existing Apify run and its dataset before retrying. A lost response may hide a successful, charged run. Automatic replacement runs can duplicate processing. A rejected file has no successful-parsing event; review its error and fix the input first. Use only synthetic, redacted excerpts when asking for support.

## Audio or XML source cannot be downloaded
An unsigned link to a private Apify storage record is not a publicly readable
file. A successful upload alone does not prove that the Actor can fetch it.
Use the accessible-record route documented by the Actor; do not paste your
account API token into a source URL or make private storage public as a fix.
For small audio files, AUDIO_GUIDE.txt documents the local --console-json
helper that prepares base64 input. For XML, use the listing's signed-record
recipe, or the inline synthetic example to check your configuration first.
Signed links can grant access: treat them as secrets and redact support posts.
Neither Actor fetches arbitrary web pages; changing a filename or repeatedly
submitting the same inaccessible URL will not repair access.

## XML reader certificate verification error
The local Python reader needs a working CA trust bundle. XML_GUIDE.txt describes
the tested Mac configuration and its limits. Repair the trust configuration;
never disable HTTPS certificate verification. The reader uses an existing run
and does not start paid processing again.

## HEIC: prepare JSON offline before using the Console
With Python 3, run this in a private working directory containing photo.heic:

```python
import base64, json, os
from pathlib import Path

with Path("photo.heic").open("rb") as source:
    raw = source.read(10_000_001)
if not raw or len(raw) > 10_000_000:
    raise ValueError("Use a nonempty file of at most 10,000,000 bytes")
payload = {"imageBase64": base64.b64encode(raw).decode("ascii")}
fd = os.open("heic-input.json", os.O_WRONLY | os.O_CREAT | os.O_EXCL, 0o600)
with os.fdopen(fd, "w", encoding="utf-8") as output:
    json.dump(payload, output)
```

This reads at most 10,000,001 bytes to enforce the decoded-file byte limit and
creates a NEW heic-input.json with restrictive permissions on POSIX systems.
It refuses to overwrite an existing file; use a new filename or remove your
own obsolete file deliberately. Check Windows permissions separately.
The JSON contains a copy of your photo as base64: it is not encrypted. Keep it
private and delete it according to your retention policy when no longer needed.

In the Actor's Input JSON editor, replace the whole example input with this
object, inspect current pricing and set your run cap before starting. Do not
add a data:image/heic;base64, prefix or encode the base64 string again.
This preparation performs no network request and no conversion. A filename
and byte-size check cannot prove valid HEIC, supported bit depth, image count
or pixel dimensions; those are validated by the Actor. Metadata removal from
the resulting JPEG does not remove the source photo from input storage.
